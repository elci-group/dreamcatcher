# Dreamcatcher v0.1 — the Dream suite compiler

## Identity

`dreamcatcher` is a new Rust CLI crate at `/home/sal/dreamcatcher` (currently empty). It discovers `.dream` files, compiles them into a Dream IR graph, runs deterministic clustering / conflict / dependency analysis and prioritisation, and emits `.deliver` execution contracts (YAML + dreamboat-compatible JSON sidecar). Decisions per user: **freeform input format, Contract YAML + JSON sidecar output, deterministic-only reasoning (no LLM)**.

Pipeline: `discover → parse → IR graph → cluster/merge → conflict analysis → dependency analysis → prioritisation → emit .deliver DAG + report`

## Step 2 — Input format: `.dream`

Human-writable TOML with a prose body. Schema (serde, `#[serde(default)]` everywhere):

```toml
id = "dream-001"                    # optional; derived from filename hash if absent
title = "Kaptaind forward-compat"
created = 2026-08-22                # optional
[intent]
statement = "old .kaptaind files should keep working"   # required
kind = "opportunity|desire|observation|proposal|concern|change"
[subject]
name = "kaptaind"                   # project/repo/tool/system
tags = ["config", "schema"]
[evidence]
items = ["migration broke in v0.3"]
[meta]                               # all optional
priority_hint = "low|medium|high|critical"
effort_hint = "small|medium|large"
risk_hint = "low|medium|high"
depends_on = ["dream-017"]
conflicts_with = ["dream-042"]
supersedes = ["dream-009"]
requires_capabilities = ["schema detection"]
open_questions = ["which schema registry?"]
```

Module `src/dream/{mod.rs, parse.rs, model.rs}`: model structs, TOML parser with clear error reporting (file, line, field), filename-derived stable ids (`dream-<sha-prefix>`).

## Step 3 — Discovery

`src/discover.rs`: `walkdir` from a roots list (CLI `--root` repeatable, default `.`), collect `**/*.dream`, skip `.git`/`target`/hidden dirs, dedupe by content hash. Index with mtime + sha256 for provenance.

## Step 4 — Dream IR graph

`src/ir.rs`: in-memory graph. Nodes = dreams (full fields + provenance), edges typed: `depends_on`, `conflicts_with`, `supersedes`, `related_to` (auto), `converges_with` (cluster membership). Serializable to JSON (`dreamcatcher ir --emit ir.json`) for debugging/humans.

## Step 5 — Deterministic analysis passes

`src/analyze/` with `mod.rs` + one file per pass:

- **clustering** (`cluster.rs`): group by (normalised subject name, shared tags, token-overlap on intent/evidence above a threshold). Each cluster becomes a candidate higher-order deliverable; singletons pass through.
- **conflict** (`conflict.rs`): explicit `conflicts_with` + detected (same subject, contradictory `kind`, or supersedes cycles). Conflicts never merge — they emit a `needs_human_decision` deliverable.
- **dependency** (`dependency.rs`): resolve `depends_on` (missing reference = error; cycle = error reported, sub-DAG emitted excluding cycle), topological order.
- **reasoning/synthesis** (`synthesize.rs`): per cluster, deterministically build the contract: merge intent statements, union evidence/capabilities/constraints, roll up priority = max(member hints) with rules, detect capability gaps (required_capabilities with no satisfying dream/cluster).
- **prioritisation** (`prioritise.rs`): score = f(priority, expected-value proxy = evidence count + cluster size, risk, effort) — pure functions, unit-tested, weights configurable in `dreamcatcher.toml`.
- Any interpretation gap → `required_human_decisions` list on the emitted contract, never silently resolved.

## Step 6 — Output: `.deliver` execution contracts

`src/emit/{mod.rs, yaml.rs, json.rs}`:

1. **Contract YAML** `deliverables/<slug>.deliver` — the user's example shape: `scope, objective, required_capabilities, constraints, acceptance, priority, dependencies, execution: Dreamboat`, plus a `provenance` block listing source dream ids/paths/hashes (every decision traceable).
2. **Dreamboat JSON sidecar** `<slug>.deliver.json` — mapped onto dreamboat's `JourneyPayload`/`TechnicalDirective` model (title, problem_statement from evidence, proposed_solution from synthesised intent, acceptance_criteria, repositories = relative subject names, risk, execution_mode = "plan", directive ids from dream ids). Unsigned in v0.1; signing hook left as a documented TODO for dreamboat.
3. **Manifest** `deliverables/manifest.json`: the deliver DAG (ids, dependencies between deliverables, scores, human-decision flags) — this is what Dreamboat will walk.
4. **Report** (`src/report.rs`): human + `--format json` summary: dreams found, clusters, conflicts, deliverables emitted, human decisions required. Exit code non-zero on parse errors or unresolved cycles.

## Step 7 — CLI

`dreamcatcher [OPTIONS] [COMMAND]`; flags `--root <DIR>` (repeat), `--config <PATH>`, `--out <DIR>` (default `./deliverables`), `--format text|json`, `--dry-run` (analysis + report, no writes), `--strict` (warnings are errors). Subcommands: `init` (scaffold `dreamcatcher.toml`), `validate` (parse-check all dreams, no emit), `ir` (dump IR graph), `completions`, `schema` (hand-written JSON Schema of the `.dream` format, mirroring deliver's `src/schema.rs` pattern).

## Step 8 — Tests & docs

- `tests/integration_test.rs`: `CARGO_BIN_EXE_dreamcatcher` + `tempfile` sandboxes. Cases: single dream → one deliverable; three convergent dreams → one merged deliverable with provenance of 3; explicit conflict → human-decision deliverable; missing `depends_on` → error + non-zero exit; cycle detection; `validate` on malformed TOML; determinism (same input → byte-identical output, run twice, compare hashes).
- Unit tests on clustering similarity, scoring, and yaml emission ordering (sorted keys for determinism).
- `README.md`: suite topology (Dream → Dreamcatcher → Deliver/Dreamboat → Dreamsequence), `.dream` format guide, example end-to-end.
- `man/dreamcatcher.1` troff page, version-synced.
